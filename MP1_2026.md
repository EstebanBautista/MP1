## Descripción general

A continuación se presentan los lineamientos para el desarrollo de múltiples diseños multihilo (memoria compartida) aplicadas al código Enemy Cars (ver Repositorio). Se debe implementar un sistema donde los vehículos enemigos se generen y sus posiciones se actualicen de forma asíncrona mediante hilos. El proyecto sigue un diseño cliente servidor, donde el *backend* se encarga de generar los datos de movimiento, mientras que el *frontend* muestra los vehículos enemigos y aplica las posiciones recibidas.

### Objetivos

Al completar este micro-proyecto, los estudiantes aprenderán a:

- Crear y gestionar la ejecución paralela mediante C++ `std::thread` o POSIX `pthread`.
- Descomponer un problema en tareas independientes (tres variantes).
- Diseñar soluciones basadas en hilos para simulaciones en tiempo real.
- Gestionar datos compartidos entre hilos.

---

## Diseño 1: Hilos Independientes

En este diseño, cada vehículo enemigo tiene su propio hilo de ejecución. Cada hilo es responsable de actualizar únicamente un vehículo.

```
Carro 1 ---> Thread 1
Carro 2 ---> Thread 2
Carro 3 ---> Thread 3
Carro 4 ---> Thread 4
```

---

## Diseño 2: Hilo único de Actualización

En este diseño existe un solo hilo encargado de actualizar todos los vehículos.

```
            A Thread
               |
   --------------. . .-------
   |             |          |
 Car1          Car2  . . .  CarN
```

---

## Diseño 3: Hilo para cada tipo de vehículo

En este diseño existe un solo hilo encargado de actualizar todos los vehículos de un tipo, rojos, verdes, negros etc.

```
            A Thread
               |
   -------------- . .. ------
   |             |          |
 Car(red)     Car2 (red) . . .  CarN (red)
```

---

## Diseño 4: Hilo asíncrono para vehículos

En este diseño existe un grupo fijo de hilos que ejecutan tareas. Los vehículos no tienen un hilo permanente (evalúe una implementación sin *websockets*). Los hilos toman las solicitudes desde una cola.
